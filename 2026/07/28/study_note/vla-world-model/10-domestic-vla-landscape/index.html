1. 先分清哪些系统是真正的 VLA

类别 接口 代表 不应误解为
端到端 VLA 图像/语言/状态 → 机器人动作 GR-3、G0-VLA、RynnVLA、Xiaomi-Robotics-0、LingBot-VLA 只会视觉问答的 VLM
高层具身 VLM 图像/语言 → 子任务、目标、空间推理 G0-VLM、Embodied-R1.5 主干 高频关节控制器
VLA—世界模型联合 动作与未来观测共同建模 RynnVLA-002、LingBot-VA 普通无条件视频生成
数据/仿真平台 数据、场景、评测或仿真 Galaxea Dataset、AgiBotWorld、Genie Sim 动作策略模型

企业演示表明系统能在某个设置完成任务，但不自动说明其模型是端到端 VLA，也不等于可独立复现。

3. GR-3：三类数据各自解决什么

GR-3 技术报告将其定义为大规模 VLA，面向新物体、新环境、抽象指令、少量数据适配、双臂、长时程与移动操作。其数据配方可写成：

互联网数据没有机械臂动作；人类动作与机械臂运动学不同；机器人数据最可执行却昂贵。三者并非重复数据。ByteMini 是双臂移动机器人本体，GR-3 是策略模型，不能混称。

报告中的 π₀ 比较只能理解为作者实验：需核对机器人、数据、后训练量、任务与成功判定是否相同。本次未确认完整训练数据、完整权重及第三方复现包，因此证据等级是“官方技术报告和内部实验”。

4. G0：高层规划与低层控制为何分开

G0 / Galaxea Open-World Dataset提出双系统：

flowchart LR
    I[多相机图像] --> P[G0-VLM 高层规划器]
    L[语言指令] --> P
    P --> S[子任务序列]
    S --> A[G0-VLA 低层执行器]
    I --> A
    R[机器人状态] --> A
    A --> O[连续机器人动作]

高层低频地判断“先抓哪个、下一阶段是什么”；低层高频地根据视觉和状态修正连续动作。论文的三阶段训练为：跨本体预训练、单一本体预训练、任务后训练。单一本体阶段仍有必要，因为动作维度、相机、控制频率、运动学和归一化语义一致，可减少跨本体冲突并提升闭环稳定性。

Galaxea 数据强调在真实生活/工作环境中以一致本体采集及子任务语言标注；它与 Open X-Embodiment 的多本体异构聚合互补。本文不猜测其论文未公开的频率、ROS 版本或权重状态。

5. RynnVLA：从人类视频先验到动作—世界统一

RynnVLA-001 官方入口的核心是从人类示范视频学习操作先验。视频能提供任务顺序、手眼协调、对象状态变化；它不能直接提供可执行的机器人关节命令，仍须使用机器人数据后训练。

RynnVLA-002将连续动作生成和动作条件图像生成统一。官方仓库列出连续 Action Transformer、腕部相机与 state 输入，并公开 LIBERO、LeRobot 的模型、训练和评测入口。

[
a_{t:t+H}=\pi_\theta(o_t,s_t,l),\qquad
\hat o_{t+1:t+H}=W_\phi(o_t,a_{t:t+H})
]

前式输出未来动作块；后式预测动作可能带来的未来观察。未来预测为动作学习提供“后果是否合理”的辅助监督，但统一训练不等于每个控制周期都要在线生成未来视频。官方 LIBERO 分数仍属于作者设置，不能直接外推到工业场景。

6. 智元：Action CoT 与世界模型平台

ACoT-VLA 官方仓库关注“动作空间中的中间推理”。它不同于自然语言 CoT：

中间表示 与动作执行距离
语言步骤 较远
视觉子目标 中等
粗动作轨迹 / 动作意图 较近 
flowchart TD
 I[图像 + 语言] --> V[VLM]
 V --> E[Explicit Action Reasoner]
 E --> C[粗动作轨迹]
 V --> M[Implicit Action Reasoner]
 M --> P[隐式动作先验]
 C --> A[最终动作专家]
 P --> A

名称中有 CoT 不代表具有可审计的自然语言思维链。仍要核查粗轨迹标签、EAR/IAR/权重是否完整开放，以及它是否改善真实闭环恢复。

Genie Envisioner是世界基础平台；GE-Sim/Genie Sim 是仿真、场景构建、数据生成与评测平台。视频/世界模型预训练可提供动作后果先验，但还需动作后训练；仿真平台不是 VLA 本身。

7. 小米：异步执行与数据规模化

Xiaomi-Robotics-0 论文和官方仓库称其为 4.7B 开源 VLA：跨本体机器人轨迹与视觉语言数据共同预训练，并为实时性设计异步动作块执行。仓库列出 2026-02 的权重、推理/评测资料以及 2026-04 的后训练代码。

flowchart LR
 C[Camera / State Thread] --> P[Policy Server]
 P --> N[新 Action Chunk]
 B[旧动作缓冲区] --> A[时间对齐 / 过渡融合]
 N --> A
 A --> R[Robot Controller]

新 chunk 生成时，机器人仍需执行旧 chunk。直接切换会不连续；直接丢弃旧块会出现控制空窗。工程上要按绝对控制时间对齐、丢弃过 deadline 预测，并只在重叠区平滑。这不同于 Temporal Ensemble：后者融合同一绝对时刻的多次预测，异步执行首先处理推理与控制线程不同步。

附件要求的 Xiaomi-Robotics-1、UMI 和自动语言标注路线，本次未找到标题完全一致且可核查的完整官方报告/仓库，因此明确标为待主来源核验，不根据演示断言其数据、权重或部署接口已经开放。

8. LingBot 与 Embodied-R1.5

LingBot-VLA是 Robbyant 的 VLA 基础模型路线；其深度版本试图补足预训练 VLM 语义特征缺乏精确三维几何的问题。深度可能是输入、特征或蒸馏监督；若深度相机噪声/内参与训练不同，也会降低跨相机泛化。

LingBot-VLA 2.0报告约 60,000 小时数据（50,000 小时机器人轨迹、20 种机器人配置，10,000 小时第一视角视频），并扩展到头、腰、底盘与灵巧手等自由度，使用未来预测代理任务。

flowchart TD
 I[当前图像 / 语言 / 状态] --> B[VLA Backbone]
 B --> A[动作预测头]
 B --> S[未来语义特征预测头]
 B --> D[未来深度 / 几何预测头]

多本体数据需要动作 mask、频率处理、缺失状态处理和质量加权，不能直接拼数组。未来预测通常可作为训练期辅助，是否在线 rollout 需按部署代码确认。

LingBot-VA将视频和动作交错建模：

[
o_t,a_t,o_{t+1},a_{t+1},…
]

它是动作条件、因果的世界模型路线，不等于普通视频生成。视频预测可约束动作后果，动作也约束未来视频的可达性；世界分支对实时性的代价必须通过实测确定。

Embodied-R1.5首先是具身基础模型（EFM），论文称其可用少量动作数据微调成 VLA。其规划、空间 grounding 和纠错适合高层闭环，但仍需独立低层策略执行高频连续控制，不能简单等同于传统大规模动作预训练 VLA。

9. 横向比较与批判性结论

模型 类型 世界模型 公开证据状态
GR-3 VLA 非主张 技术报告；完整复现包未确认
G0 双系统 VLM+VLA 辅助/未在摘要明确 论文；其余以官方仓库为准
RynnVLA-002 VLA+世界模型 是 代码、模型、训练/评测入口
ACoT-VLA 动作推理 VLA 否 官方实现；独立复现未确认
Genie Envisioner 世界基础平台 是 官方实现；非 Genie Sim
Xiaomi-Robotics-0 实时 VLA 否 权重、推理、评测、后训练代码
LingBot-VLA VLM+动作专家 否 官方仓库；逐项看 README
LingBot-VLA 2.0 动力学辅助 VLA 训练期辅助 论文；代码/权重以项目页为准
LingBot-VA 视频—动作联合 是 官方仓库
Embodied-R1.5-VLA EFM+动作头 间接 论文/项目页；低层部署待核查

国内路线并非脱离 RT-2、π₀、ACT 和世界模型另起炉灶：它们分别将重点放在数据规模、规划执行分层、动作中间表示、异步实时接口与动作后果预测。是否“超过国外模型”不能凭单个 benchmark 判断；必须统一本体、数据、后训练量、任务分布、成功判定和试验次数。

数据规模也不等于能力：人类视频域差异、自动语言标签噪声、异构控制频率、相机配置与低质量示教都可能削弱泛化。LIBERO/CALVIN/SimplerEnv 指标与真实机器人长时间稳定运行亦不是同一件事。
