1. 从一次“动作方向反了”的失败开始

相机在机器人右前方。训练数据把末端增量写成基座坐标系：Δx_B=+0.02 m 表示向机器人前方移动 2 cm。部署端却把同一数组解释成相机坐标系。相机稍转动，+x_C 已不再对应机器人前方，于是模型看起来“懂目标”，却朝侧面走。

这不是模型泛化问题，而是 action_frame 丢失。任何数据集至少要能回答：谁采集、何时采集、相对哪个坐标系、单位是什么、控制器怎样解释它？

2. 一个推荐样本：字段和 shape 同时写清

state.shape == action.shape == [14] 并不表示两者可交换。例：前 7 维 state 可能是左臂关节角；前 7 维 action 可能是左臂 [Δx,Δy,Δz,Δrx,Δry,Δrz,gripper]。shape 检查只能发现维度错误，不能发现语义错误。

3. 坐标系：先决定 action 在哪里定义

[
{}^B T_E(t+1)={}^B T_E(t),{}^E!\Delta T
]

({}^B T_E) 是末端相对机器人基座的位姿；({}^E!\Delta T) 是末端系增量。若动作是在基座系定义，则组合顺序不同。不要把同一个 delta_pose 同时叫“相对末端”和“相对世界”；这两个命令在旋转后数值意义不同。

表示 优点 最常见故障
关节位置/速度 直接贴近低层控制器 机器人构型变化时迁移困难
末端绝对位姿 任务目标直观 标定、IK 分支与跳变
末端增量位姿 局部闭环稳定，常用于示教 frame 混淆、频率错配
力矩/力控制 适合接触任务 安全要求高，数据质量敏感

4. 时间同步：相机 30 Hz、状态 100 Hz、控制 20 Hz 怎么对齐？

设第 240 个控制时刻为 t=12.000 s。选择最近前视帧 11.997 s、腕部帧 12.006 s、插值后的状态 12.000 s，最大偏差为 6 ms；若阈值是 20 ms，可形成有效样本。若固定相机帧是 11.940 s，则不能悄悄与新状态拼接。

[
\Delta t_{sync}=\max_i |t_i-t_{control}|\leq\tau
]

(\tau) 是允许的同步偏差。训练集应保存原始时间戳和对齐策略；只保存“拼好”的数组，日后无法解释抓取前为什么总提前/滞后。

5. 归一化：训练时的 2 cm 到底如何变成网络数字？

假设训练集的 Δx 均值为 0.001 m、标准差为 0.015 m。一次 Δx=0.021 m 的示教会变成：

[
\tilde a_x=\frac{0.021-0.001}{0.015}=1.33
]

部署端输出 1.33 必须用同一份训练统计量反归一化才回到 0.021 m。不能为新工作台重新计算均值方差，否则策略输入/输出语义被改写。

6. 从 episode 到 ACT/DP 窗口

一条 20 Hz、30 秒示教有 600 帧。若 H=100，合法起点是 0…500；取 t=240 时，观测来自第 240 帧，监督目标来自 240…339。按 episode 切分 train/val/test，不能把同一轨迹的第 240 帧给训练、第 241 帧给验证，否则模型几乎看过验证答案。

6.1 逐项算一遍坐标变换

机器人里最常见的难题不是“会不会写矩阵”，而是忘记问矩阵的上标和下标。令 ({}^B R_E) 表示末端坐标系 (E) 相对基座 (B) 的旋转。若策略给出末端局部坐标系增量：

[
{}^E\Delta p=[0.01,0,0]^T
]

它的语义是“沿夹爪自己朝向的 x 轴移动 1 cm”。若此时夹爪已绕 z 轴转了 90°，那么在基座系中：

[
{}^B\Delta p={}^B R_E{}^E\Delta p=[0,0.01,0]^T
]

也就是说，数组仍然是 [0.01, 0, 0]，真实世界中的运动方向却由末端姿态决定。把它误当作基座系增量，机器人会往错误方向走。

6.2 四元数为何会造成“看似随机翻转”

同一个旋转既可写成 (q=[x,y,z,w])，也可写成 (-q)。若数据集没有统一符号，相邻帧可能从 (q) 跳到 (-q)，虽然物理姿态连续，L2 损失却会把它当作巨大跳变。

6.3 observation、action 的时间索引必须成对定义

“第 t 帧图像对应第 t 个动作”这句话不够精确。以下三种标签完全不同：

约定 监督的语义 适合什么控制器
(o_t\rightarrow a_t) 当前观察后立即发出的命令 实时速度/增量控制
(o_t\rightarrow a_{t+1}) 预测下一控制周期目标 管线有固定一周期延迟
(o_t\rightarrow [a_t,…,a_{t+H-1}]) 未来 H 步动作块 ACT、Diffusion Policy

如果相机端的曝光—传输已经带来 40 ms 延迟，而日志把动作下发时刻错误地当成图像采样时刻，训练会产生“看见过去、模仿未来”的标签错位。模型常表现为动作总是慢半拍。

6.4 数据质量不是只看缺失值

一个 episode 看起来字段齐全，也可能不适合训练。建议按以下层次检查：

  1. 完整性：图像、状态、动作、目标、时间戳是否缺失；
  2. 物理合理性：关节角是否超限，速度是否出现不可能尖峰；
  3. 时序合理性：相邻帧时间差是否接近控制周期；
  4. 语义合理性：动作是否与指定坐标系、夹爪定义一致；
  5. 任务质量：是否完成，失败发生在哪个阶段，是否有人接管。

例如，某段轨迹中的夹爪开度从 0.8 在一帧跳到 -0.3，数组类型没有报错，但它可能是设备重启、归一化错误或通讯异常。这种片段要有可追溯的过滤原因，不能静默混入训练集。

7. 上线前 8 项数据审计

  1. 所有相机是否统一 RGB/BGR 和 resize/crop？ 2. joint order 是否显式保存？ 3. 四元数顺序是 xyzw 还是 wxyz？ 4. action frame 是否写入 metadata？ 5. 是否保存控制频率与每步持续时间？ 6. timestamp 是采样时间还是到达时间？ 7. train 统计量是否随 checkpoint 一同版本化？ 8. 原始回放能否还原控制命令？

8. 本节总结与自测

可靠数据不是“有图、有 action”就够了；它必须让每个张量的 frame、单位、顺序、时间和控制解释可追溯。ACT、Diffusion 和 VLA 都建立在这个契约之上。

  1. delta_pose 在基座系和末端系为何不同？ 2. 20 ms 阈值如何决定？ 3. 为什么同形状数组也会产生错误？ 4. 为什么按 episode 切分？ 5. 哪些统计量必须随模型发布？
