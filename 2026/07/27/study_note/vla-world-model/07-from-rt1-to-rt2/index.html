从 RT-1 到 RT-2：VLA 如何把网络语义带进机器人动作

上一篇：Transformer 与 VLM ｜ 下一篇：OpenVLA 与 OFT

1. 这篇文章解决什么问题？

用一条技术脉络区分三件事：RT-1 的大规模真实机器人控制、PaLM-E 的具身多模态语言模型、RT-2 的视觉—语言—动作联合学习。它们不是同一个系统的简单参数升级。

2. 前置知识

阅读本篇前应理解 token、因果序列和离散/连续动作差异，见 06。

3. 从“捡起罐子”开始

RT-1 把图像和任务指令输入 Transformer，输出离散化机器人动作；RT-2 将动作表示进 token 空间，使视觉问答等互联网数据可与机器人轨迹共享序列学习接口。它们仍需要真实控制数据把语义落到机体与坐标系。

4. 核心概念

RT-1 采用图像编码、TokenLearner 压缩视觉 token、FiLM 用语言调制视觉特征，并离散化动作。PaLM-E 将连续传感器/视觉表示送入语言模型，擅长具身推理，但不等同于低层实时控制器。RT-2 的标志性思路是把机器人动作编码为 token，并与 Web VQA 等视觉语言数据联合训练，以迁移语义概念；动作 token 的量化误差、长序列延迟和离散格点限制仍存在。

4.1 从连续动作到 token：数值究竟损失在哪里？

假设末端 (\Delta x) 的训练范围为 [-0.04, 0.04] m，将其均匀量化为 256 个 bin。每个 bin 宽约为 0.08/255 = 0.000314 m，即 0.314 mm。真实动作 0.0123 m 会被编码为一个整数 token，部署时再解码到该 bin 的代表值；这个误差在单维很小，但与旋转、夹爪、连续控制频率叠加后会影响精细接触。

量化表必须和 checkpoint 一起保存；bin=0 是否对应最小值、夹爪 token 是独立词表还是连续维度，都是 action spec 的一部分。

4.2 RT-1、PaLM-E、RT-2 该怎样读

问题 RT-1 PaLM-E RT-2
核心接口 图像/语言→离散动作 连续传感表示→语言模型 VLM 序列→动作 token
关键收获 规模化真实机器人数据与 Transformer 控制 具身信息可进入语言模型 Web 视觉语言语义可与机器人动作共训
不应推断 任意新物体都能抓 可直接替代 20Hz 伺服 action token 没有量化/延迟代价

4.3 RT-1 的“视觉特征”为什么还要压缩

一张 224×224 图像经 ViT 切成 14×14 个 patch 后已有 196 个视觉 token；若再加多相机、历史帧和语言 token，Transformer 的序列长度会迅速增加。注意力的计算量会随长度平方增长，因此 RT-1 使用 TokenLearner 从空间特征中学习一小组“该看哪里”的加权 token。

它可以被直观地理解成：做“拿起红色罐子”时，模型没必要将桌面每块纹理同等对待；更有价值的 token 应该聚焦罐子、夹爪、障碍物和目标区域。压缩不是无损的，若 token 数过少，细小物体、接触点或遮挡边缘可能直接消失。

FiLM（Feature-wise Linear Modulation）则让语言指令调制视觉特征：

[
\text{FiLM}(f,g)=\gamma(g)\odot f+\beta(g)
]

同一画面里有红、蓝两个方块时，“拿红方块”和“拿蓝方块”可通过不同的 (\gamma,\beta) 强调不同视觉特征。它不是语言直接生成电机命令，而是为后续动作头提供任务相关的视觉表示。

4.4 动作 token 是怎样排成一句“机器人语言”的

假设每一步动作有 7 个维度：三维平移、三维旋转和夹爪。一个简化的串行格式可能是：

自回归 Transformer 依次预测这些 token。好处是可复用语言模型成熟的分类目标和词表机制；代价是：

  1. 每个维度都要一次或多次 token 预测，推理长度增加；
  2. 第一个 token 错了，后面的条件上下文会受影响；
  3. 连续控制被限制在有限栅格，接触前的微调受量化分辨率影响；
  4. 不同维度的物理关系要由模型从序列顺序中学习。

也存在“每个动作维度一个并行分类头”的设计。它延迟更低，但少了动作维度之间自回归条件化。没有一种 token 化对所有任务都最好；评估时要同时报告每维 bins、动作串长度、控制频率和端到端延迟。

4.5 Web 数据与机器人数据如何真正发生迁移

互联网视觉语言数据可以教模型“什么是倾倒、抽屉、可抓取的把手、把物体放在容器里”这类语义关联；机器人轨迹才教它：在某台机械臂、某个相机、某个坐标系下，动作 token 对应多大的位移。

可把混合训练目标概念性地写为：

[
\mathcal L=\lambda_{robot}\mathcal L_{robot-action}
+\lambda_{web}\mathcal L_{vision-language}
]

这里的两个 (\lambda) 不是可有可无的超参数。若 Web 数据压倒性更多，模型可能很会描述“杯子在桌上”，却没有足够的动作监督；若机器人数据过少且任务单一，语义迁移难以落到可靠控制上。混合比例、采样策略和冻结/微调哪些模块，都应是实验报告的一部分。

5. 方法整体架构

6. 训练过程

RT-1 主要监督机器人轨迹；RT-2 在视觉语言与机器人任务的混合数据上学习。数据采样配比决定模型会更偏语言能力还是控制能力，不能仅以模型总数据量判断可操作性。

7. 推理和部署过程

将输出 token 反量化为动作，再按频率发送给安全控制层。需要检查 tokenization 的 bin 边界、夹爪编码和反归一化，与 03 的动作契约一致。

8. 公式解释

[p(a_{1:T}\mid o,g)=\prod_{t=1}^{T}p(a_t\mid a_{<t},o,g)]

(o) 是观测、(g) 是指令、(a_t) 是离散动作 token；因果分解表示每一步只依赖此前已生成 token，不代表可忽略闭环观测。

9. 简化伪代码

bins 的 shape 可能是 [B, Da] 或一个自回归 token 序列；dequantize 后才是 [B, Da] 的物理动作。反量化之后仍要做归一化逆变换、frame 检查和工作空间限幅，不能直接发送到机械臂。

10. 与前后方法的关系

RT-2 说明 VLA 的形成：高层语义和动作监督可共训；OpenVLA 进一步给出开放权重与可研究的实际接口。

11. 常见误解

动作 token 不是 VLA 的定义；它只是一个接口选择。Web 数据带来概念迁移，也不会自动提供接触动力学标签。

12. 实际工程问题

记录每个维度的量化区间和饱和率；若动作经常落在最小/最大 bin，首先排查归一化和标定，而非立即扩大模型。

13. 本文总结

RT-1 建立了规模化真实机器人 Transformer 控制，RT-2 把视觉语言语义与动作 token 联合，构成早期 VLA 的关键范式。
