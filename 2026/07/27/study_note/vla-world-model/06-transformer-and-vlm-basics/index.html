从相机图像到机器人 Token：ViT、Transformer 与 VLM 的可跟做基础

本篇只解决一件事：机器人工作台上的一张相机图像，怎样变成 VLA 可以与语言、关节状态一起处理的 token？

上一篇：Diffusion Policy ｜ 下一篇：从 RT-1 到 RT-2 ｜ 术语：VLM、VLA

1. 先看最终要解决的机器人问题

桌面上有一个红色方块、一只夹爪和一个蓝色盒子。指令是“把红色方块放进蓝色盒子”。相机给出的是一张 RGB 图像，控制器需要的是一个动作，例如基座坐标系的末端增量：

视觉语言动作模型（VLA）不会直接把 224×224×3 个像素逐一送给动作头；它首先把图像压缩成一串固定维度的视觉 token，再与语言 token、机器人状态 token 融合。理解这条数据链，比背诵“ViT 使用 Transformer”重要得多。

2. 1.1 Patch Embedding：图片如何变成 token？

2.1 从一张相机图到 196 个小块

设训练时把前视相机裁剪并缩放到 224×224，每个 patch 的边长为 P=16。那么图像会被切成：

[
N=\frac{H}{P}\times\frac{W}{P}=\frac{224}{16}\times\frac{224}{16}=14\times14=196
]

这里每个符号都对应真实输入：

符号 数值 意义
(H,W) 224, 224 预处理后的图像高、宽
(P) 16 一个 patch 的边长
(N) 196 送入 Transformer 的视觉 token 数量
(C) 3 RGB 通道数
(D) 768 每个 token 的 embedding 维度（示例）

一个原始 patch 有 16×16×3=768 个像素值。它经过线性投影后得到一个长度为 D=768 的向量；这个维度碰巧相同并不表示“像素原样保留”，参数化投影会重组信息。

2.2 shape 必须能在纸上推出来

B 是 batch size。以 B=8 为例，最后一行的含义是：一次训练输入 8 张相机图，每张有 196 个视觉 token，每个 token 有 768 个浮点数。

2.3 为什么代码里常用 Conv2d？

Patch Embedding 可被实现为 kernel_size=P, stride=P 的卷积：卷积核覆盖一个 patch，步长正好跳到下一个 patch，因此没有重叠。它等价于“切块 → 展平 → 对每块做同一个线性层”，但更高效。

2.4 机器人里最容易踩的坑

相机采集到的常是 uint8 [H,W,3]，而上面模块需要 float32 [B,3,H,W]。正确转换包括通道换位、归一化和 batch 维；训练与部署的裁剪、RGB/BGR 顺序、均值方差必须完全一致。在真实机器人上，颜色顺序错误看起来“不太明显”，却会令预训练视觉编码器失效。

3. 1.2 Position Embedding：为什么 token 还需要位置？

把 196 个 patch 展平后，纯 self-attention 并不知道哪个 token 原来在左上角、哪个在夹爪附近。若不加入位置，交换两个 patch 的顺序对注意力计算没有区别；但机器人必须区分“方块在夹爪左边”与“方块在右边”。

最常见做法是给每个 token 加可学习的位置向量：

[
z_0{(i)}=x_{patch}{(i)}+p^{(i)},\quad i=1,\ldots,N
]

(x_{patch}^{(i)}) 是第 (i) 个 patch 的视觉 embedding，(p^{(i)}) 是该空间位置的位置 embedding，(z_0^{(i)}) 是送入 Transformer 的输入。实际 VLM 可能使用二维插值位置编码、RoPE 或其他变体；但先要掌握它解决的是“空间顺序丢失”而非“物体检测”。

**检查点：**多相机时不能简单把三路 token 拼在一起却不给相机 ID/位置语义；否则模型可能把腕相机中的夹爪当成固定相机中的夹爪。常见方案是每路相机各自编码，再加入 camera embedding。

4. 1.3 Self-Attention：一个视觉 token 如何“看见”另一个？

对 token 矩阵 (X\in\mathbb R^{N\times D})，注意力首先做三次线性投影：

[
Q=XW_Q,\quad K=XW_K,\quad V=XW_V
]

再计算：

[
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
]

以抓取任务解释：一个覆盖“红色方块”的 patch token 可以把“夹爪”“蓝色盒子”“桌面边缘”的 token 作为信息来源。注意力权重不是可验证的因果解释，但它提供了按内容相关性聚合全局上下文的机制。

196×196 说明每个 patch 都可以与所有 patch 建立关系。这也是分辨率翻倍时显存迅速增长的原因：token 数约随面积增长，注意力矩阵约随 token 数平方增长。

5. 1.4 从 ViT 到 VLM：语言和机器人状态放在哪里？

VLM 的本质不是“给图像再加一句文本”，而是把不同模态转换到兼容的隐藏维度 (D)，然后让模型在明确的序列/交互规则中融合它们。一个简化的 VLA 输入可写成：

机器人 state 不应被藏在 prompt 文本里。关节角、夹爪宽度、末端位姿等连续量经 MLP 投影成 state token，能保留数值精度并避免 tokenizer 量化误差。

这里的 405 = 196 + 196 + 1 + 12。它是调试多模态模型时应当打印的第一项：token 数量不对，通常代表相机、历史帧或语言模板没有按训练配置进入模型。

6. 1.5 CLIP、SigLIP、DINOv2：该关心什么，不该关心什么？

编码器类型 预训练偏好 对 VLA 的直接含义 不能自动解决的事
CLIP / SigLIP 图像—文本语义对齐 “红色方块”“盒子”等语言概念更容易对齐 精确接触与坐标标定
DINOv2 自监督视觉表征 跨外观、局部特征常更稳健 语言指令理解
任务微调视觉编码器 当前机器人数据 可适应相机、桌面和工具 数据稀少时容易过拟合

不要问“哪个视觉编码器最好”，先问任务失败在哪里：如果机器人把“红块”和“蓝盒”搞混，检查语言—视觉语义；如果已识别物体却总在接触前偏 2 cm，先检查相机外参、动作 frame、延迟和训练数据覆盖。

8. 排错清单：模型前向能跑，不代表 token 是对的

  1. **shape 正确但颜色错：**检查 BGR/RGB、归一化均值方差和 resize/crop 顺序。
  2. **相机换位：**固定相机与腕相机的 key 顺序在训练、推理中必须相同。
  3. **state token 漂移：**部署状态的关节排序、单位、归一化统计必须使用训练版本。
  4. **token 数突变：**检查是否漏掉历史帧、多相机，或更改了图像分辨率。
  5. **语言无效：**做同一画面、两条互斥指令的对照测试；不能只看多任务总成功率。
  6. **视觉很准但抓不准：**优先排查时间同步、坐标系和控制延迟，而不是盲目微调 VLM。

9. 本节总结

ViT 的 Patch Embedding 把 [B,3,H,W] 变成 [B,N,D]；位置编码保留空间顺序；self-attention 建立 patch 间上下文；VLM 再把视觉、语言、本体状态投影到同一隐藏空间；VLA 最后通过动作头把表示变为控制命令。这个接口是理解 RT-1、RT-2、OpenVLA 与 π₀ 的共同地基。

10. 自测：不要只会背定义

  1. 224×224、P=16 时为什么是 196 个 token？
  2. 若图像改为 448×448，token 数与注意力矩阵大小分别怎样变化？
  3. Conv2d(kernel=16,stride=16) 为什么等价于无重叠 patch 切分？
  4. 为什么关节状态更适合变成连续 state token 而不是一句文本？
  5. 相机 BGR/RGB 颠倒后，shape 检查为什么抓不住这个错误？
